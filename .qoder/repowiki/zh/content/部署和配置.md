### 环境变量与配置安全

**重要安全更新** ⚠️

当前项目存在严重的安全风险：**根目录的 `.gitignore` 文件没有忽略 `.env` 文件**，这意味着敏感的环境变量可能被提交到版本控制系统中。

#### 环境变量优先级机制
- 系统环境变量 > .env 文件
- 这种设计允许在 CI/CD 环境中覆盖本地配置

#### 安全最佳实践

**立即修复措施：**
1. **添加 .env 到根目录的 .gitignore**
   ```
   # 在根目录 .gitignore 中添加
   .env
   .env.local
   .env.*.local
   ```

2. **检查并提交历史中的敏感信息**
   - 如果 .env 已被提交，需要清理 Git 历史
   - 轮换所有泄露的 API 密钥

3. **使用环境变量模板**
   - 创建 `.env.example` 作为模板
   - 不包含实际值，只包含变量名和注释

#### 生产环境部署策略

**推荐的环境变量管理方式：**

1. **云平台环境变量注入**
   - Vercel：使用平台设置中的环境变量功能
   - AWS：使用 Systems Manager Parameter Store 或 Secrets Manager
   - Azure：使用 Key Vault
   - Google Cloud：使用 Secret Manager

2. **容器化部署**
   - Docker：使用 `docker run -e` 或 docker-compose secrets
   - Kubernetes：使用 ConfigMap 和 Secret
   - 永远不要将敏感信息打包进镜像

3. **CI/CD 流水线**
   - 使用平台的加密环境变量功能
   - 避免在日志中打印敏感信息
   - 实施最小权限原则

### 紧急安全修复步骤

**如果发现 .env 文件已被提交到版本控制：**

1. **立即轮换所有 API 密钥**
   - 访问 https://console.anthropic.com/ 获取新的 API 密钥
   - 更新所有使用旧密钥的服务

2. **清理 Git 历史**
   ```bash
   # 移除 .env 文件的历史记录
   git filter-branch --force --index-filter \
     'git rm --cached --ignore-unmatch .env' \
     --prune-empty --tag-name-filter cat -- --all
   
   # 强制推送到远程仓库
   git push --force --all
   git push --force --tags
   ```

3. **更新 .gitignore**
   ```
   # 在根目录 .gitignore 中添加
   .env
   .env.local
   .env.*.local
   *.env
   ```

4. **通知团队成员**
   - 要求所有克隆仓库的开发者重新拉取最新代码
   - 提醒他们更新本地环境变量配置
