## 1. 整体方案

该仓库是一个教学型 Java Agent 运行时，没有引入任何第三方异常框架（如 Spring、Jakarta EE），也没有自定义业务异常类。错误处理采用 **Java 标准异常 + 局部 try/catch** 的轻量方式：
- 调用方期望的错误（参数非法、状态不合法）通过 `IllegalArgumentException` 抛出；
- 基础设施/IO/网络失败通过 `IllegalStateException` 包装后向上冒泡；
- 部分“可恢复”或“非致命”的 IO 错误被直接吞掉（`catch (IOException ignored)`）或返回字符串形式的错误消息。

项目不存在全局异常处理器、拦截器、中间件或 `try/finally` 资源清理的统一入口——每个模块自行决定捕获范围。

## 2. 关键文件与职责

| 文件 | 错误处理方式 |
|---|---|
| `common/JsonUtils.java` | Jackson 序列化/反序列化异常统一包装为 `IllegalStateException("JSON 序列化/反序列化失败", e)`，禁止上层感知具体 JSON 库异常 |
| `common/AnthropicClient.java` | HTTP 4xx/5xx 响应体直接拼入 `IllegalStateException` 文本以便调试；`IOException | InterruptedException` 统一转为 `IllegalStateException("Anthropic API 调用失败", e)`，并在 catch 中调用 `Thread.currentThread().interrupt()` 恢复中断标志 |
| `common/WorkspacePaths.java` | 路径逃逸校验失败抛 `IllegalArgumentException("Path escapes workspace: ...")`，用于防止模型通过 `../` 访问工作区外文件 |
| `tasks/TaskManager.java` | 任务不存在抛 `IllegalArgumentException`；目录创建/读写/删除失败抛 `IllegalStateException`；`loadAll()` 在扫描失败时优雅降级返回空列表 |
| `tools/TodoManager.java` | 业务校验：Todo 数量上限、必填字段、状态枚举、同时仅允许一个 `in_progress`，全部以 `IllegalArgumentException` 表达 |
| `team/MessageBus.java` | 发送失败返回字符串 `"Error: ..."`；读取失败返回包含错误信息的系统消息对象；类型校验失败也返回字符串错误 |
| `skills/SkillLoader.java` | 构造期与解析期 IO 异常使用 `catch (IOException ignored)` 静默忽略，使缺少 skills 目录或单个文件损坏不影响启动 |
| `background/BackgroundManager.java`、`context/CompressionService.java`、`tasks/WorktreeManager.java`、`team/TeammateManager.java` | 均遵循“IO 失败 → `IllegalStateException` 包装”的模式 |

## 3. 架构与约定

### 3.1 两层异常语义
- **参数/业务规则错误**：使用 `IllegalArgumentException`，表示调用方传入了不符合契约的数据（如 Todo 为空、超过 20 条、状态不在枚举内、任务 ID 不存在、路径逃逸）。这类错误通常由工具层或校验层立即拒绝。
- **基础设施/外部依赖错误**：使用 `IllegalStateException` 包裹底层异常（`IOException`、Jackson `JsonProcessingException`、HTTP 异常等），并附带中文描述性消息，例如 `"无法创建 .tasks 目录"`、`"保存 worktree 索引失败"`、`"压缩会话失败"`。这使调用方无需关心具体是磁盘不可写还是 JSON 格式错误。

### 3.2 分层错误传播策略
- **工具层（tools/）**：严格校验输入，直接抛 `IllegalArgumentException`，让 Agent 能据此修正提示。
- **服务层（tasks/, team/, context/, background/）**：将 IO 异常包装为 `IllegalStateException` 向上传播，因为上层（AgentRuntime / Launcher）通常是单进程主循环，最终会打印堆栈。
- **基础设施层（common/）**：`JsonUtils` 作为唯一 JSON 入口，屏蔽 Jackson 细节；`WorkspacePaths` 集中安全路径校验；`AnthropicClient` 把 HTTP 错误体原样放入异常信息便于调试兼容端点。

### 3.3 静默容错（Graceful Degradation）
对于“非致命”场景，代码选择吞掉异常而非中断流程：
- `SkillLoader` 构造期扫描 `skills/` 目录时，若目录不存在或某个 `SKILL.md` 读失败，直接 `ignored`，保证无技能也能运行。
- `MessageBus.readInbox()` 读取失败时返回一条包含错误信息的系统消息对象，而不是抛异常，使 Agent 仍可继续消费其他收件箱。
- `TaskManager.loadAll()` 在遍历任务文件时遇到 IO 异常，当前条目跳过，外层 `loadAll()` 捕获后返回空列表，避免整个看板崩溃。

### 3.4 线程与中断
`AnthropicClient.createMessage` 在捕获 `InterruptedException` 后显式调用 `Thread.currentThread().interrupt()` 恢复中断标志，再包装为 `IllegalStateException` 抛出，确保上层线程池能感知中断。

## 4. 约束与规则

- **不定义自定义异常类**：全仓未发现 `class XxxException extends Exception` 或 `RuntimeException` 的定义，所有业务异常均复用 JDK 内置异常。
- **JSON 操作必须走 `JsonUtils`**：`JsonUtils` 是唯一暴露的序列化入口，内部统一注册 `JavaTimeModule` 并禁用时间戳输出，所有 `JsonProcessingException` 一律包装为 `IllegalStateException`，禁止上层直接处理 Jackson 异常。
- **工作区路径必须经 `safeResolve`**：`WorkspacePaths.safeResolve` 强制检查 `resolved.startsWith(workdir)`，逃逸时抛 `IllegalArgumentException`，这是防止模型通过相对路径越权访问文件的唯一安全边界。
- **HTTP 错误保留响应体**：`AnthropicClient` 对 4xx/5xx 响应直接将 `response.body()` 拼入异常消息，便于对接智谱、OpenRouter 等兼容端点时定位问题。
- **工具方法同步化**：`TaskManager`、`MessageBus` 的关键方法标注 `synchronized`，并发写入失败时通过 `IllegalStateException` 上报，而不是静默丢弃。
- **无全局错误处理器**：`Main` 仅委托给 `SFull.main(args)`，未设置 `UncaughtExceptionHandler`、Servlet Filter、Spring ControllerAdvice 等全局捕获机制，错误最终由 JVM 默认策略打印到控制台。

## 5. 总结

该仓库的错误处理风格高度朴素：用 `IllegalArgumentException` 表达“调用方错了”，用 `IllegalStateException` 表达“环境/IO/网络出错了”，对可恢复的加载阶段采用 `ignored` 静默容错。它没有统一的错误码体系、没有业务异常层次结构、也没有前端/后端统一的错误响应格式——这与它是一个教学演示项目、重点在于展示 Agent 行为而非健壮生产系统的设计目标一致。
