## 1. 使用的系统与工具

- **后端（Java）**：使用 `io.github.cdimascio:dotenv-java` 库加载根目录的 `.env` 文件，并配合 `System.getenv()` 读取系统环境变量；通过 Jackson (`jackson-databind`、`jackson-datatype-jsr310`) 序列化/反序列化 JSON。
- **前端（Next.js）**：通过 `package.json` 中的脚本在构建前执行 `scripts/extract-content.ts`，将 Markdown/JSON 数据提取为静态内容；多语言文案位于 `web/src/i18n/messages/{en,ja,zh}.json`。
- **Maven**：通过 `pom.xml` 的 `<properties>` 集中声明 Java 版本（17）、编码（UTF-8）和依赖版本（如 Jackson 2.17.2），并通过 `exec-maven-plugin` 注入 `file.encoding`、`sun.stdout.encoding`、`sun.stderr.encoding` 等 JVM 运行参数。

## 2. 关键文件与包

| 文件 | 作用 |
|---|---|
| `src/main/java/com/learnclaudecode/common/EnvConfig.java` | 统一的环境变量读取器，封装 `.env` 与系统环境变量优先级 |
| `src/main/java/com/learnclaudecode/common/WorkspacePaths.java` | 工作区路径抽象，定义 `.tasks`、`.team`、`skills`、`.transcripts`、`.worktrees` 等约定目录 |

## 3. 架构与设计约定

### 3.1 环境变量加载与优先级
`EnvConfig` 在构造时创建 `Dotenv.configure().ignoreIfMissing().load()`，随后通过 `getenv(key)` 方法实现**系统环境变量优先于 `.env` 文件**的覆盖策略：先查 `System.getenv(key)`，为空再查 dotenv，仍为空返回 `Optional.empty()`。其中 `MODEL_ID` 通过私有 `require()` 强制要求存在，缺失时抛出 `IllegalStateException`；`ANTHROPIC_API_KEY` 允许为空字符串；`ANTHROPIC_BASE_URL` 默认回退到 `https://api.anthropic.com`。

### 3.2 应用装配顺序
`AppContext` 是唯一的装配入口，遵循固定顺序：
1. 读取 `EnvConfig` 与 `WorkspacePaths`（工作区根目录）
2. 创建基础服务：`AnthropicClient`、`CommandTools`、`TodoManager`
3. 创建扩展机制：`SkillLoader`、`CompressionService`、`TaskManager`、`BackgroundManager`、`MessageBus`、`TeammateManager`、`WorktreeManager`
4. 将所有服务注入 `AgentRuntime`，由它驱动主循环
这种分层装配使得每个 `Sxx` 阶段入口类无需重复装配代码，也清晰展示了 Claude Code 风格 Agent 的分层结构。

### 3.3 阶段能力配置（Feature Flags）
`StageConfig` 是一个 Java record，字段包括 `prompt`、`enableTodoNag`、`enableCompression`、`enableBackground`、`enableInbox`、`subagentWritable`、`autonomousTeammates`、`tools`、`systemTemplate`。每个阶段（s01~s12、sFull）通过静态工厂方法返回不同的配置组合，本质上是**在同一 `AgentRuntime` 上逐步打开能力开关**。`systemPrompt()` 会在运行时把 `${WORKDIR}` 和 `${SKILLS}` 占位符替换为实际值。

### 3.4 工作区目录约定
`WorkspacePaths` 将工作区根目录规范化为绝对路径，并提供安全解析 `safeResolve()`——所有文件操作必须经过此方法，若解析后路径不在 workdir 下则抛出 `IllegalArgumentException("Path escapes workspace")`，防止模型通过 `../` 逃逸。约定目录包括：`.tasks`（任务数据）、`.team/inbox`（团队协作消息）、`skills`（技能描述）、`.transcripts`（会话转录）、`.worktrees`（隔离工作树索引）。

### 3.5 前端配置
Next.js 前端通过 `package.json` 的 `predev` / `prebuild` 钩子在启动/构建前执行 `tsx scripts/extract-content.ts`，将 `web/src/data/scenarios/*.json` 与 `annotations/*.json` 等数据提取为静态资源；多语言文案按 `web/src/i18n/messages/{en,ja,zh}.json` 组织，通过 `web/src/lib/i18n-server.ts` 与 `i18n.tsx` 提供 i18n 支持。

## 4. 约定与约束

- **环境变量命名规范**：`MODEL_ID`（必填）、`ANTHROPIC_API_KEY`（可选）、`ANTHROPIC_BASE_URL`（可选，默认 Anthropic 官方地址）。
- **`.env` 文件位置**：项目根目录，用于本地开发；CI 或 IDEA 运行配置中可通过系统环境变量覆盖。
- **工作区路径安全**：所有文件读写必须通过 `WorkspacePaths.safeResolve()`，禁止直接拼接用户输入路径。
- **阶段配置不可变**：`StageConfig` 是 record，各阶段通过静态工厂方法返回不可变实例，新增阶段需新增工厂方法而非修改已有配置。
- **JVM 编码统一**：通过 `pom.xml` 中 `exec-maven-plugin` 的 `<systemProperties>` 强制设置 UTF-8 编码，避免跨平台输出乱码。
- **前端数据提取前置**：`npm run dev` 与 `npm run build` 之前都会自动执行 `npm run extract`，确保数据文件同步。

## 5. 适用性说明
本仓库确实实现了一个轻量但完整的配置系统：后端通过 `.env` + 系统环境变量加载运行时密钥，通过 `StageConfig` 管理功能开关，通过 `WorkspacePaths` 约定工作区目录结构；前端通过 `package.json` 脚本与 i18n JSON 管理构建期与运行期配置。因此该类别适用且证据充分。
